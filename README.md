# Boba 🧋

A tiny browser agent: a no-build Violentmonkey userscript plus a dependency-free Go localhost server.

**Target:** Firefox-based browsers (including Zen) + Violentmonkey on macOS.

> Automatic execution, no approval prompts. Boba can submit forms, run arbitrary page JavaScript, overwrite workspace files, and send sensitive DOM values (including passwords) to OpenRouter. Use trusted/test pages. Page prompt injection remains a risk.

## Start

Requires Go 1.25+; Node is only needed for development tests.

```sh
go build -o boba .
./boba init
```

Edit **`config.json` in this project directory**:

- `api_key`: your OpenRouter API key.
- `model`: an OpenRouter model ID supporting tool calling; also vision if attaching images.
- `port`: default `8787`.
- `pairing_token`: generated by `init`; copy this to Boba's settings.

The example model is a configurable starting point, not a promise of availability. Real config is ignored by Git. Do not put it inside the workspace.

```sh
./boba serve
```

The server listens on `127.0.0.1`, not your LAN. For a different config location use `./boba serve -config /path/to/config.json`.

## Install in Zen / Firefox

1. Install/enable Violentmonkey in your Firefox-based browser.
2. Create a **new script** in the Violentmonkey dashboard.
3. Replace the editor contents with [userscript/boba.user.js](userscript/boba.user.js) and save.
   - A standalone binary can export the same source: `./boba userscript > /tmp/boba.user.js`.
   - This source contains no API key or pairing token.
4. Reload an ordinary web page (extensions cannot run on all browser-internal or protected pages).
5. Open Boba via Violentmonkey's **Open Boba** menu command, or **⌥⇧B** (Option + Shift + B).
6. In Boba settings, enter `http://127.0.0.1:8787` and the pairing token from `config.json`, then **Save & connect**.

The default shortcut is `Alt+Shift+B`. If your browser intercepts it, use the menu command and configure another shortcut. Existing saved shortcuts are preserved when updating; change an older `Meta+Shift+B` setting manually in Boba settings. Shortcut syntax uses `Meta`, `Ctrl`, `Alt`, `Shift` plus one letter.

## Use

Examples:

- 「把這個頁面翻譯成繁體中文，保留原版面。」
- 「隱藏右側欄，把正文加寬。」
- 「把所有連結整理成 Markdown，存到 output/links.md。」
- 「填入測試資料，但不要提交表單。」
- 「產生適用這個網站的 userscript，存到 userscripts/，並提供安裝按鈕。」

Press Enter to send; Shift+Enter inserts a newline. Follow-ups retain the conversation until the document reloads or you choose **New**. Hiding the panel does not stop the agent.

**Stop** aborts pending requests and subsequent tool calls. It does not undo completed changes or guarantee interruption of already-running JavaScript. Model requests are capped at 20 steps per message; send a follow-up to continue.

### Workspace prompts

The server creates:

```text
~/Documents/boba/
├── prompts/
├── output/
└── userscripts/
```

Copy the included prompts, if desired:

```sh
cp examples/prompts/*.md ~/Documents/boba/prompts/
```

Use the prompt dropdown or type `/translate additional instructions`. Nested prompt names such as `/writing/rewrite` are supported. Prompt files are instructions, not executable trusted plugins.

### Images / vision

Click **Image**, or paste a screenshot into the prompt field. PNG/JPEG/WebP, up to 1.5 MB; click the attachment label to remove it. The configured model must support vision.

This does **not** silently capture the tab or screen. Automatic screenshot capture is not implemented; it would need a separately agreed capture/permission approach.

### Generated userscripts

Boba saves a complete `.user.js` and can show an **Install in Violentmonkey** button. The button opens a five-minute capability URL; the pairing token is never included in the URL. You complete installation in Violentmonkey.

Installation handoff still needs validation with your actual Violentmonkey version. If its URL interception fails, paste the saved file into a new script in its dashboard.

Files can be overwritten without approval. `trash_file` copies a regular file (up to 32 MiB) into the real macOS `~/.Trash`, then removes the source only after the copy is synced. It does not trash directories/symlinks or use Finder automation. Permission failures preserve the original.

## Implementation

- [userscript/boba.user.js](userscript/boba.user.js): UI, tools, bounded agent loop; no bundler or runtime npm dependencies.
- [server.go](server.go): authenticated OpenRouter proxy, files, prompts, expiring install links.
- [workspace.go](workspace.go): traversal-resistant `os.Root` file operations and atomic writes.
- [docs/MVP.md](docs/MVP.md): agreed scope and acceptance scenarios.

The proxy owns model/credentials; the userscript sends only messages and tool definitions. File tools are confined to `~/Documents/boba`, including symlink resolution. The page receives no host-tool bridge. These precautions are **not** a sandbox against malicious generated JavaScript or compromised browser/page code.

Page JavaScript uses the page's Function constructor. CSP may block it, which is reported as a tool error. Structured DOM tools remain preferable. Same-origin iframe inspection is supported; cross-origin frames and protected cookies/page objects remain subject to browser restrictions. Tools use synthetic events, so some sites may require real user gestures. Full document navigation terminates the current task; SPA navigation can continue while the agent survives.

## Development & tests

```sh
go test -race -cover ./...
go vet ./...
npm ci
npm test
npm run check
npx playwright install firefox
npm run test:browser
```

- Go tests cover authentication, proxying/cancellation/errors, path confinement, prompts, writes, Trash behavior, and installation tickets. Trash tests use temporary directories, not your real Trash.
- Node/jsdom tests cover tool-loop history, cancellation, bounds, DOM tools, and the full UI.
- Playwright tests run a real Firefox engine, **with mocked GM APIs and model responses**, including image attachment and Stop.
- The local demo has also been checked through the existing browser MCP in the running Firefox-based browser. This is **not** proof of live Violentmonkey or OpenRouter integration.

Run a safe, deterministic UI demo:

```sh
npm run demo
# http://127.0.0.1:8790/
```

It has no API key or host file access. Its model and GM bridge are explicitly mocked. To test the real installed userscript against the plain fixture instead, serve `examples/` using a local static server; do not use the mocked demo as an integration test.

### Remaining live validation

- Actual Zen + Violentmonkey injection, private GM storage, localhost requests, and CSP behavior.
- Your OpenRouter key/model completing the five acceptance scenarios.
- Violentmonkey installation handoff from expiring localhost URLs.
- Automatic screenshot approach, if required later.

API references used: [Violentmonkey privileged APIs](https://violentmonkey.github.io/api/gm/), [injection metadata](https://violentmonkey.github.io/api/metadata-block/#inject-into), [OpenRouter chat schema](https://openrouter.ai/docs/api/reference/overview), [screen-capture permissions](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia).
