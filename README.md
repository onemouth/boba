# Boba 🧋

A tiny browser agent: a no-build Violentmonkey userscript plus a dependency-free Go localhost server.

**Target:** Firefox-based browsers (including Zen) + Violentmonkey on macOS.

> Automatic execution, no approval prompts. Boba can submit forms, run arbitrary page JavaScript, overwrite workspace files, and send sensitive DOM values (including passwords) to OpenRouter. Use trusted/test pages. Page prompt injection remains a risk.

## Start

Requires Go 1.25+; Node is only needed for development tests.

```sh
go build -o boba .
./boba init
```

Edit **`config.json` in this project directory**:

- `api_key`: your OpenRouter API key.
- `model`: an OpenRouter model ID supporting tool calling; also vision if attaching images.
- `max_tokens`: maximum output per model request; default **16384** when omitted or zero. Must be positive otherwise and supported by the selected model. Restart the server after changing it.
- `port`: default `8787`.
- `pairing_token`: generated by `init`; copy this to Boba's settings.

The example model is a configurable starting point, not a promise of availability. Real config is ignored by Git. Do not put it inside the workspace.

```sh
./boba serve
```

The server listens on `127.0.0.1`, not your LAN. For a different config location use `./boba serve -config /path/to/config.json`.

## Install in Zen / Firefox

1. Install/enable Violentmonkey in your Firefox-based browser.
2. Create a **new script** in the Violentmonkey dashboard.
3. Replace the editor contents with [userscript/boba.user.js](userscript/boba.user.js) and save.
   - A standalone binary can export the same source: `./boba userscript > /tmp/boba.user.js`.
   - This source contains no API key or pairing token.
4. Reload an ordinary web page (extensions cannot run on all browser-internal or protected pages).
5. Open Boba via Violentmonkey's **Open Boba** menu command, or **⌥⇧B** (Option + Shift + B).
6. In Boba settings, enter `http://127.0.0.1:8787` and the pairing token from `config.json`, then **Save & connect**.

The default shortcut is `Alt+Shift+B`. If your browser intercepts it, use the menu command and configure another shortcut. Existing saved shortcuts are preserved when updating; change an older `Meta+Shift+B` setting manually in Boba settings. Shortcut syntax uses `Meta`, `Ctrl`, `Alt`, `Shift` plus one letter.

### Panel missing on YouTube / strict-policy pages

Update the installed userscript to **0.1.2** or later and fully reload the page. UI construction now uses DOM APIs instead of `innerHTML`, so it does not need a Trusted Types policy or relaxed CSP. The browser startup path also ignores a site's CommonJS-like `module` object, prevents duplicate panels, and logs `[Boba] UI initialization failed` plus a **Boba startup error** menu command if initialization fails.

Strict CSP/Trusted Types startup is covered by a real Firefox regression test with mocked GM APIs; this is not yet proof of the updated script working in the user's live YouTube tab. If the panel is still absent after updating, report that diagnostic menu's message. Opening the panel does not require the localhost server; arbitrary page JavaScript may still be blocked by site CSP.

## Chrome DevTools Snippet

No userscript manager is required for this entry point. Start/restart the updated Go server, then copy `devtools/boba-snippet.js` into **Chrome DevTools → Sources → Snippets** and run it on the target page.

It opens a separate **localhost chat/controller window**. Confirm the target origin and enter the pairing token **only in that window**, never in the target page or snippet. The page bridge exposes DOM tools only; server API authentication and the no-CORS policy are unchanged.

See [DevTools setup, security, and limitations](devtools/README.md). Reload ends the snippet session; rerun it to reconnect. Popup blockers, COOP, and page CSP can limit functionality. This is not the planned Firefox extension.

## Use

Examples:

- 「把這個頁面翻譯成繁體中文，保留原版面。」
- 「隱藏右側欄，把正文加寬。」
- 「把所有連結整理成 Markdown，存到 output/links.md。」
- 「填入測試資料，但不要提交表單。」
- 「產生適用這個網站的 userscript，存到 userscripts/，並提供安裝按鈕。」

Press Enter to send; Shift+Enter inserts a newline. Follow-ups retain the conversation until the document reloads or you choose **New**. Hiding the panel does not stop the agent.

**Stop** aborts pending requests and subsequent tool calls. It does not undo completed changes or guarantee interruption of already-running JavaScript. Model requests are capped at 20 steps per message; send a follow-up to continue.

### Long tasks and output limits

Userscript **0.1.4+** asks the model to produce small, complete batches for any long task, not just translation. Page/file changes use separate complete tool calls; long prose can use the internal `checkpoint` tool to retain progress and automatically request the next response. A checkpoint is in-memory conversation state, not a saved file or cross-reload task recovery. Large file chunks should use distinct numbered paths; `write_file` does not append.

If a completion ends with `finish_reason: length`, Boba discards the **entire** incomplete response, including any apparently complete tool calls inside it. Nothing from that response is displayed or executed. It requests a smaller batch again, at most **two retries per user instruction**, preserving accepted history and confirmed earlier work. It never concatenates partial JavaScript/JSON or automatically replays prior tool calls. These retries and checkpoints count toward the existing 20-step cap. Repeated truncation or the step cap stops the run; send a follow-up with a smaller scope to continue.

The server now defaults to `max_tokens: 16384`, also reported by authenticated `/api/health`. This is an upper bound, not a promise every model/provider will honor it. The model must follow batching instructions; batching is not a deterministic semantic splitter. Restart the server and update the installed userscript to use both changes. The DevTools version shares this behavior after replacing the snippet with its regenerated version and reloading the controller.

### Structured progress & failure history

Userscript **0.1.5+** adds an expandable **Progress & history** ledger, shared by the regenerated DevTools version. The runtime distinguishes acknowledged tool returns, failed reads, calls that never dispatched, and mutations with **uncertain** effects after errors/Stop/disconnect. Model checkpoints remain explicitly unverified claims; they cannot promote an operation to success.

On follow-up, the model receives compact execution facts, file paths, recent failures and the reported cursor. Exact repeats of unresolved mutations, plus writes/trash to the same unresolved file path, are blocked until you inspect the real effect and explicitly review the row while idle. A user review preserves the original failure and is not automatic verification or undo. Top-level URL changes stale the cursor and require fresh inspection.

The ledger is bounded, in-memory only; no cross-reload recovery or full Pi-style compaction is claimed. **New** clears records but leaves page/file changes intact. Tool success counts are not percentages or verified whole-task completion. See [progress semantics, privacy, memory limits and Pi design references](docs/progress.md).

### DOM tools without eval

Userscript **0.1.6+** adds `read_text`, `insert_text`, `set_style`, `remove_inserted` and `verify_dom`. They support paginated full DOM text, stable original-source IDs, idempotent pure-text insertion, allowlisted inline styling, ownership-only cleanup and DOM/geometry checks. They use prewritten APIs rather than `Function()` or HTML parsing, so text tasks can work even when arbitrary page JavaScript is CSP-blocked.

Try: 「保留原文，使用結構化工具逐段加入繁體中文對照，先讀 5 段，完成後驗證配對。」 Same-origin iframe reading is supported; cross-origin restrictions, complex reader pagination and screenshot limitations remain. Source changes cause refusal rather than injection into a guessed paragraph. Known local compilation/preflight rejection is now `not_executed`; runtime failures can still be uncertain.

See [tool arguments, safety, cleanup and limits](docs/structured-dom.md). Existing workspace prompts, including `bilingual.md`, are unchanged. Update the userscript and reload, or regenerate/replace the snippet and restart the server for its embedded controller assets.

### Workspace prompts

The server creates:

```text
~/Documents/boba/
├── prompts/
├── output/
└── userscripts/
```

Copy the included prompts, if desired:

```sh
cp examples/prompts/*.md ~/Documents/boba/prompts/
```

Use the prompt dropdown or type `/translate additional instructions`. Nested prompt names such as `/writing/rewrite` are supported. Prompt files are instructions, not executable trusted plugins.

For paragraph-aligned bilingual reading, use `/bilingual 翻譯目前文章，保留原文並加入繁體中文對照`. The included `bilingual.md` adapts the Firefox bilingual-EPUB skill to Boba's tools: stable paragraph indices, batched translation, idempotent injection, same-origin iframe readers, pagination checks, and optional JSON/Markdown/HTML export. Automatic screenshots and EPUB packaging are explicitly unsupported; navigation and visual checks must be reported honestly. Close/reopen the panel to refresh the prompt picker after adding a file. No server restart or userscript update is required.

### Images / vision

Click **Image**, or paste a screenshot into the prompt field. PNG/JPEG/WebP, up to 1.5 MB; click the attachment label to remove it. The configured model must support vision.

This does **not** silently capture the tab or screen. Automatic screenshot capture is not implemented; it would need a separately agreed capture/permission approach.

### Generated userscripts

Boba saves a complete `.user.js` and can show an **Install in Violentmonkey** button. The button opens a five-minute capability URL; the pairing token is never included in the URL. You complete installation in Violentmonkey.

Installation handoff still needs validation with your actual Violentmonkey version. If its URL interception fails, paste the saved file into a new script in its dashboard.

Files can be overwritten without approval. `trash_file` copies a regular file (up to 32 MiB) into the real macOS `~/.Trash`, then removes the source only after the copy is synced. It does not trash directories/symlinks or use Finder automation. Permission failures preserve the original.

## Implementation

- [userscript/boba.user.js](userscript/boba.user.js): UI, tools, bounded agent loop; no bundler or runtime npm dependencies.
- [server.go](server.go): authenticated OpenRouter proxy, files, prompts, expiring install links.
- [devtools/](devtools/README.md): Chrome snippet, protected-origin controller, and page RPC adapter; static assets served by [devtools.go](devtools.go).
- [workspace.go](workspace.go): traversal-resistant `os.Root` file operations and atomic writes.
- [docs/MVP.md](docs/MVP.md): agreed scope and acceptance scenarios.

The proxy owns model/credentials; the userscript sends only messages and tool definitions. File tools are confined to `~/Documents/boba`, including symlink resolution. The page receives no host-tool bridge. These precautions are **not** a sandbox against malicious generated JavaScript or compromised browser/page code.

Page JavaScript uses the page's Function constructor. CSP may block it, which is reported as a tool error. Structured DOM tools remain preferable. Same-origin iframe inspection is supported; cross-origin frames and protected cookies/page objects remain subject to browser restrictions. Tools use synthetic events, so some sites may require real user gestures. Full document navigation terminates the current task; SPA navigation can continue while the agent survives.

## Development & tests

```sh
go test -race -cover ./...
go vet ./...
npm ci
npm test
npm run check
npm run build:devtools
npx playwright install chromium firefox
npm run test:browser
```

- Go tests cover authentication, proxying/cancellation/errors, path confinement, prompts, writes, Trash behavior, and installation tickets. Trash tests use temporary directories, not your real Trash.
- Node/jsdom tests cover tool-loop history, cancellation, bounds, DOM tools, and the full UI.
- Playwright tests run a real Firefox engine, **with mocked GM APIs and model responses**, including image attachment and Stop. Chromium snippet tests use a real Go server and temporary workspace with only OpenRouter mocked, covering cross-origin RPC, token separation, follow-up, Stop, reload disconnect, and strict CSP.
- The userscript remains standalone/no-build. Developers regenerating DevTools artifacts run `npm run build:devtools`; committed assets let the Go server work without Node at runtime.
- Live installed-userscript testing through the existing browser MCP in Zen has verified real localhost/OpenRouter requests, DOM inspection and modification, form filling without submission, follow-up translation, and workspace file writing. The output was independently checked at `~/Documents/boba/output/boba-smoke-links.md`. No GM/model mocks were used for this check.
- Two installed Boba instances were detected on that page. Only one was paired and tested; disable the duplicate script/manager to avoid overlapping panels. The specific manager owning each instance was not independently identified.

Run a safe, deterministic UI demo:

```sh
npm run demo
# http://127.0.0.1:8790/
```

It has no API key or host file access. Its model and GM bridge are explicitly mocked. To test the real installed userscript against the plain fixture instead, serve `examples/` using a local static server; do not use the mocked demo as an integration test.
