# Boba 🧋

**Boba: Open Browser Agent** — your browser, your model, your agent.

Operate web pages with natural-language instructions. Boba pairs a standalone Violentmonkey userscript with a lightweight Go server that connects to OpenRouter.

- **Firefox / Zen:** an in-page chat panel through Violentmonkey.
- **Chrome:** a DevTools snippet with a separate localhost chat window.
- **macOS:** workspace file tools and an OS-sandboxed shell.

> Boba executes automatically, without approval prompts. It can submit forms, change pages and overwrite workspace files. Page data—including sensitive form values—may be sent to your model. Use trusted pages.

## Quick start

Requires **Go 1.25+** and an OpenRouter API key. Node.js is only needed for development.

```sh
git clone https://github.com/onemouth/boba.git
cd boba
go build -o boba .
./boba init
```

Edit the generated `config.json`:

| Setting | Description |
| --- | --- |
| `api_key` | Your OpenRouter API key. |
| `model` | A model supporting tool calling; vision support is needed for images. |
| `max_tokens` | Output limit per request; defaults to `16384`. Must be supported by your model. |
| `port` | Local server port; defaults to `8787`. |
| `pairing_token` | Generated by `init`; copy it into Boba settings. |

Keep `config.json` in the project directory, **outside `~/Documents/boba`**. It is gitignored. Never paste credentials into a web page or commit them.

```sh
./boba serve
```

The server listens only on `127.0.0.1`. Restart it after changing configuration. To use another configuration file: `./boba serve -config /path/to/config.json`.

### Firefox / Zen

1. Install [Violentmonkey](https://violentmonkey.github.io/).
2. Create a new script, paste [userscript/boba.user.js](userscript/boba.user.js), and save. You can also export it with `./boba userscript > /tmp/boba.user.js`.
3. Reload a web page and press **Option + Shift + B** (`Alt+Shift+B`), or choose **Open Boba** from the Violentmonkey menu.
4. In Boba settings, enter `http://127.0.0.1:8787` and your pairing token, then **Save & connect**.

The shortcut is configurable. Enable only one Boba installation to avoid duplicate panels.

### Chrome

Run [devtools/boba-snippet.js](devtools/boba-snippet.js) in **DevTools → Sources → Snippets**. Enter the pairing token only in the localhost controller window it opens. See [Chrome setup](devtools/README.md).

## Usage

Try asking Boba to:

- Translate an article while keeping the original text.
- Hide the sidebar and widen the main content.
- Save the page's links as Markdown to `output/links.md`.
- Fill a form with test data without submitting it.
- Generate a userscript and offer an installation link.

**Enter** sends; **Shift+Enter** adds a newline. Follow-ups keep the conversation within the current document. **Stop** cancels pending work but does not undo changes. **New** clears the conversation and progress, not page or file effects. Hiding the panel does not stop a task.

Use **Progress & history** to inspect failures or uncertain effects before retrying. Long tasks run in small batches, with a 20-model-step limit per instruction; send a follow-up to continue. Reloading ends the session—there is no automatic recovery.

Attach or paste PNG/JPEG/WebP images up to 1.5 MB with a vision-capable model. Boba does not capture screenshots automatically.

### Workspace and prompts

Files live under `~/Documents/boba`, with `prompts/`, `output/` and `userscripts/` directories. To install the example prompts:

```sh
cp examples/prompts/*.md ~/Documents/boba/prompts/
```

Choose a prompt from the panel or type `/translate additional instructions`. Nested names such as `/writing/rewrite` work too. Close/reopen the panel to refresh the prompt list.

Generated userscripts are saved under `userscripts/`. Their installation links expire after five minutes; you complete installation in Violentmonkey. If the link is not recognized, paste the saved script into its dashboard.

## Safety and limitations

- Structured DOM tools work without eval; arbitrary page JavaScript may be blocked by CSP. Cross-origin frames and browser-protected pages remain restricted.
- File tools are confined to the workspace. Bash uses a macOS deny-default sandbox, with no network or inherited server environment. It is not a full VM or resource-quota system.
- **Only `trash_file` moves files to Trash. Shell `rm` and other destructive commands can permanently delete workspace data.**
- Stop cannot reliably interrupt running page JavaScript or detached shell processes. Errors may leave partial effects.
- Prompt injection remains a risk. The shell sandbox does not make page content trustworthy or sandbox browser JavaScript.
